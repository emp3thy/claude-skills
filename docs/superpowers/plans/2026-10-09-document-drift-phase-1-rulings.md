Each line says what was decided, why, and what it costs if wrong. Behaviour-changing rulings are also recorded as amendments in the spec's section 10.

- Ruling: R12 tree entries resolve doc-relative first, then root-relative (Task 6) - nested docs write trees relative to their own directory - cost if wrong: none (root fallback kept).
- Ruling: R13 a path token's span covers only `text` (the path), never a stripped `:<n>`/`#L<n>` suffix; plan Task 4 said the opposite, which would make a replace drop the suffix - deletion units are whole items/rows/lines/links so they never need the suffix in the span - cost if wrong: none.
- Ruling: R14 the ratio filter drops only `^\d+/\d+$` and `^[A-Za-z]/[A-Za-z]$`; the plan's `^[\w]{1,3}/[\w]{1,3}$` would drop real paths like `src/lib`, `cmd/api` - cost if wrong: an occasional `a/b` prose ratio reaches resolution and lands as summary-only.
- Ruling: R15 table header rows get block kind `table_header` and never `subject`; a `drift-ignore` before a table covers the contiguous table_row/table_delim run - deleting a header breaks the table; an explicit opt-out must cover the whole table - cost if wrong: none.
- Ruling: R16 tree detection: a fence is a tree iff it has >=2 glyph lines (├── └── |-- `--), or every non-empty line is a single name (optional trailing comment), >=2 lines end with `/`, and at least one line is indented deeper than a preceding `name/` line; unindented-only `name/` lists are never trees. Indentation unit = the smallest positive indentation step (glyph trees: the glyph prefix width per level). A first line `name/` with no glyph whose following lines are all its descendants is a candidate root label: tokens keep it as a path prefix in `text`, and Token gains `tree_label` (that first name without `/`, else null) so Task 6 resolves with the label first and then with it stripped. Tree lines with an unmarked description column: split the name at the first run of 2+ spaces - plan text overruled (4-col levels, root label always dropped) because it yields wrong repository paths - cost if wrong: some trees resolve via the stripped-label fallback.
- Ruling: R17 (promoted minor 4, load-bearing for Task 6) Token.target_doc is always repository-relative (doc dir joined and normalised for `x.md#f`, the doc itself for `#f`) - one rule for Task 6 - cost if wrong: none.
- Ruling: R18 subject = the first code/link/image/refdef inline of the item's first line or table cell 0; when that inline yields no token there is no subject (implementer's conservative reading confirmed) - safer for whole-item deletes - cost if wrong: some deletes demote to human prose-mention.
- Ruling: R19 a first tree line '.' or './' is a root marker: dropped with tree_label null, children are doc-relative/root paths - '.' names the doc's own directory - cost if wrong: none.
- Ruling: R20 final_name returns (frozenset({path}), None) whenever `path` exists at HEAD (no rewrite: a recreated or never-renamed path is not drift), and a chain that returns to an earlier name finishes on that name - both cases otherwise produce wrong replacements or false deletions in Task 6 - cost if wrong: none.
