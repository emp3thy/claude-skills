## Additional risks noticed while reading

1. **`churn` cannot become null when git is absent.** Section 4.2 says "When git is absent every history field is null". `test_inventory.py:81` asserts `all(e["churn"] == 0 for e in result["files"])` in a non-git `tmp_path`, and `:61` evaluates `entry["churn"] >= 0`, which raises `TypeError` on `None`. Keep `churn` at 0 and let only the new fields (`last_touched`, `authors`, `top_author_share`, and so on) be null, or rewrite both assertions; the design lists neither.

2. **Negative-space sections leak into the last PBI** (claim 6). This is the one finding that changes a user-visible output. The cheapest fix is `while cursor < n and not _is_h2(...) and not lines[cursor].startswith("# ")` in `design_parser.py:194`, with a round-trip test that the last finding's `body_md` ends at the H1.

3. **`accepted` arrives before `promote.py` learns it.** Phase 1 extends `validation.py` (s8), but the baseline write-back that gives `accepted` meaning is phase 5. In between, `promote.py:110-111` counts every status other than approved, promoted and rejected as pending, so an `accepted` finding is reported as pending. Harmless, but the phase-1 gate should either defer the status or teach `promote.py` the count in the same phase.

4. **The scan's own state files become artefacts.** `DEFAULT_IGNORE` contains `.tech-debt` (`inventory.py:72`) and `_is_ignored` matches path parts by equality (`:100-101`), so the root files `.tech-debt.yaml` and `.tech-debt-baseline.json` proposed in s4.9 and s4.12 are not ignored. They are outside `EXT_TO_LANG` today, but the s4.2 artefact walk would classify them as `config`. Add both names to the artefact walk's exclusions.

5. **`test_real_skill_md_passes` is the cut-over guard and depends on claim 7's caveats.** `test_skill_check.py:84-86` lints the real SKILL.md. Any v2 script that combines subcommands with a top-level `choices=` option fails this test with a misleading "flag not accepted" message, so the constraint belongs in the phase 3 plan.

6. **`test_parse_golden` and the design golden are byte-pinned.** `test_design_writer.py:42-50` compares the rendered document to `tests/golden/design.md` byte for byte and `test_design_parser.py:15-19` expects five pending findings from it. Section 4.14 lists the golden rewrite, but every parser test derives its input from that golden by string replacement (`status: pending`, `slug: finding-1`, `category: god-modules`), so the v2 golden must keep those exact substrings or the seven parser tests need new fixtures.

7. **Exit code 4 overload** (claim 8): a baseline write-back failure and a mid-run bundle failure would be indistinguishable to SKILL.md's exit handling.

8. **`confidence` is parsed but never rendered into a PBI today** (`bundle_writer.py:84` lists only `debt_type` and `effort`), which matches the design's intent to drop it, but a v1 document with `confidence:` in the anchor will still parse (claim 5), so "ignored on parse" in s4.16 should read "parsed and discarded".
